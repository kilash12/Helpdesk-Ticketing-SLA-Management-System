Task 2 - Helpdesk Ticketing & SLA Management System
Tech Stack
• Backend: Python using Django REST Framework or FastAPI
• Frontend: React
• Authentication: JWT using HTTP-only Cookies
• Database: PostgreSQL / MySQL / SQLite
• Background Jobs: Celery with Redis or equivalent
• Real-time Updates: WebSocket or Server-Sent Events
Task
Develop a Helpdesk Ticketing and SLA Management System where customers create support tickets and
agents manage assignment, priority, communication, SLA deadlines, escalation, and resolution.

Status Transition Rules
• Backend must enforce valid transitions.
• Examples: Open -> Assigned; Assigned -> In Progress; In Progress -> Waiting for Customer; In Progress ->
Escalated; In Progress -> Resolved; Resolved -> Closed; Resolved/Closed -> Reopened.
• Invalid direct transitions such as Open -> Closed must return a validation error.
Ticket Assignment Rules
• Admin can assign any ticket to an active agent.
• Agent can self-assign an unassigned ticket.
• Agent cannot assign a ticket to another agent.
• Assigned agent must belong to the ticket department.
• Inactive agents cannot receive new tickets.
• Reassignment history must be stored.
SLA Management
• Admin configures SLA rules by priority.
• Each rule stores First Response Time and Resolution Time.
• At ticket creation, assign the active SLA rule and calculate due timestamps.
• Store the exact SLA rule used at creation.
SLA Breach Rules
• Identify first-response breach, resolution breach, and approaching deadline.
Full Stack Interview Tasks - Second Round Page 11
• Approaching deadline means less than 20% of allowed time remains.
Background Jobs
• Check SLA deadlines
• Send SLA warning and breach notifications
• Send assignment notifications
• Send password reset email
• Auto-close resolved tickets
Auto-Close Rule
• Resolved tickets should automatically move to Closed after 72 hours if the customer does not reopen them.
Ticket Comments
• Fields: Ticket, Message, Comment Type, Created By, Created Date, Updated Date
• Comment types: Public Reply and Internal Note
• Customers can add only public replies.
• Internal notes are visible only to agents/admins.
• Comments appear in chronological order.
Attachments
• Supported: JPG, JPEG, PNG, PDF, DOCX, TXT, CSV
• Maximum size: 10 MB
• Validate extension, MIME type, file size, empty file, and filename safety.
Ticket Escalation
• Only Agent or Admin can escalate.
• Escalation reason is required.
• Priority must increase.
• Notify Admin.
• Preserve escalation history.
Customer Satisfaction Rating
• Rating from 1 to 5
• Only ticket owner can submit
• Only one feedback entry per ticket
• Allowed only for Resolved or Closed tickets
Audit Log
• Track user, action, entity type, entity ID, old value, new value, IP address, and timestamp.
• Audit logs must be immutable through normal APIs.

Concurrency Requirement
• Two agents may self-assign simultaneously.
• Only one must succeed.
• Use a database transaction or row-level lock.
• Second request should receive HTTP 409 Conflict.

Important Conditions
• Backend is the source of truth for status, permissions, and SLA calculations.
• Customers must never see internal notes.
• Users must not access another user's data by changing IDs.
• Assignment must be concurrency-safe.
• Audit logs must be immutable.
• Background jobs must be idempotent.
• Repeated SLA jobs must not create duplicate notifications.
